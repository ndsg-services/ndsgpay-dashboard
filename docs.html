Documentation API NDSGPay

Encaissez des paiements mobile money et envoyez des fonds par une API REST en JSON. Créez un compte pour obtenir vos clés API ; l'accès aux paiements réels est activé après vérification de votre dossier par notre équipe.

Base URL
# Production NDSGPay
https://ndsgpay-backend.vercel.app/api

# Authentification : utilisez votre clé secrète NDSGPay (sk_live_)
# NE PAS utiliser un token PawaPay — NDSGPay gère PawaPay pour vous
# Les requêtes POST doivent envoyer l'en-tête Content-Type: application/json
# Limites par clé API : 60 créations de paiement/min, 120 consultations/min (HTTP 429 au-delà)
# Opérateurs : contactez support@ndsgservices.com pour la liste activée sur votre compte
Endpoints
POST /api/pay/deposits Initier une collecte 
const res = await fetch("https://ndsgpay-backend.vercel.app/api/pay/deposits", {
  method: "POST",
  headers: {
    "Authorization": `Bearer ${votre_sk_live_xxx}`,
    "Content-Type": "application/json"
  },
  // Pas de depositId à envoyer : NDSGPay génère l'identifiant et vous le renvoie.
  body: JSON.stringify({
    amount: "5000",               // en XAF
    currency: "XAF",
    correspondent: "AIRTEL_GAB",  // code opérateur : AIRTEL_GAB, MOOV_GAB, MTN_MOMO_CMR, MTN_MOMO_BEN...
    msisdn: "24177000000",        // numéro du client, format international sans + ni espaces
    description: "Commande 1042"  // facultatif, vu par votre client : accents et symboles sont retirés, 22 caractères max
  })
});
const data = await res.json();

// Réponse 200
// {
//   "success": true,
//   "depositId": "b3f0c8e2-...",  // généré par NDSGPay : conservez-le pour suivre la transaction
//   "status": "INITIATED",
//   "message": "Paiement initié. Le client va recevoir une demande de confirmation sur son téléphone."
// }
//
// Erreurs
// 400  { "success": false, "error": "Champs requis manquants : msisdn" }          (liste les champs manquants)
// 400  { "success": false, "error": "Corps de requête vide ou illisible. Envoyez du JSON avec l'en-tête Content-Type: application/json." }
// 400  { "success": false, "error": "Montant invalide : indiquez un nombre positif, sans espace ni séparateur (ex : 5000)." }
// 400  { "success": false, "error": "Correspondant invalide : ..." }   ou refus de l'opérateur
// 401  clé API manquante ou invalide          403  compte non activé
// 429  trop de requêtes                       500  erreur à l'initiation (voir le champ "details")

Webhooks (NDSGPay vers votre serveur)
POST votre URL webhook Notification de statut 
// Renseignez votre URL dans Paramètres > URL webhook.
// NDSGPay envoie un POST à chaque statut final (COMPLETED ou FAILED) :
{
  "event": "deposit.updated",         // ou "payout.updated"
  "timestamp": "2026-10-11T10:15:00.000Z",
  "data": {
    "depositId": "b3f0c8e2-...",      // ou "payoutId" : l'identifiant renvoyé à la création
    "status": "COMPLETED"             // ou "FAILED"
    // ... autres champs du message PawaPay : ne vous fiez qu'à l'identifiant et au statut
  }
}

// En-têtes envoyés :
// Content-Type: application/json
// X-NDSGPay-Event: deposit.updated
// X-NDSGPay-Merchant: <votre identifiant marchand>
// X-NDSGPay-Attempt: 1                                         (numéro de la tentative d'envoi)
// X-NDSGPay-Signature: t=1760177700,sha256=<signature>    (secret affiché dans Paramètres)
//
// À savoir
// - Répondez en 2xx en moins de 5 secondes.
// - Si votre serveur ne répond pas en 2xx, NDSGPay renvoie automatiquement : après 5 min, 15 min, 1 h puis 6 h
//   (5 envois au maximum, sur 24 h). Vous pouvez aussi renvoyer à la main depuis le Journal des webhooks.
// - Vous pouvez donc recevoir le même événement plusieurs fois : identifiez-le par depositId (ou payoutId) + status
//   et ne le traitez qu'une fois. L'en-tête X-NDSGPay-Attempt donne le numéro de la tentative.
// - Ne vous reposez pas uniquement sur les webhooks : pour une transaction encore en cours après quelques
//   minutes, interrogez GET /api/deposits/:id (ou /api/payouts/:id).
// - Une transaction terminée plus tard grâce à la réconciliation automatique de NDSGPay émet aussi un webhook
//   (quelques minutes après le paiement).
// - L'historique de chaque envoi (résultat, code de réponse, durée) est visible dans votre dashboard, Paramètres, Journal des webhooks.
POST votre URL webhook Vérifier la signature (Node.js) 
const crypto = require("crypto");
const express = require("express");
const app = express();

// Vérifie que le webhook vient bien de NDSGPay (secret : Paramètres > Secret de signature webhook)
function verifierSignatureNdsgpay(corpsBrut, entete, secret, toleranceSec = 300) {
  const parts = Object.fromEntries(entete.split(",").map((p) => p.split("=")));
  const t = parts.t;
  const signature = parts.sha256;
  if (!t || !signature) return false;
  if (Math.abs(Date.now() / 1000 - Number(t)) > toleranceSec) return false;   // anti-rejeu
  const attendu = crypto.createHmac("sha256", secret).update(`${t}.${corpsBrut}`).digest("hex");
  const a = Buffer.from(attendu);
  const b = Buffer.from(signature);
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}

// IMPORTANT : vérifiez sur le corps BRUT (le texte exact reçu), jamais sur un JSON ré-sérialisé
app.post("/webhooks/ndsgpay", express.raw({ type: "application/json" }), (req, res) => {
  const corps = req.body.toString("utf8");
  const entete = req.headers["x-ndsgpay-signature"] || "";
  if (!verifierSignatureNdsgpay(corps, entete, process.env.NDSGPAY_WEBHOOK_SECRET)) {
    return res.sendStatus(400);
  }
  const evenement = JSON.parse(corps);
  // ... mettez à jour votre commande avec evenement.data.depositId (ou payoutId) et evenement.data.status
  res.sendStatus(200);
});
